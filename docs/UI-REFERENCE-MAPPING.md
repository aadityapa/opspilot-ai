# UI reference mapping

Every route and important state of OpsPilot mapped to the eight reference boards (32 screen
concepts) supplied with the September 2026 UI audit, with its status after the refinement and any
intentional difference. The reference boards contain illustrative data, invented providers and
occasional generated text; this table records where the product deliberately diverges from them
because the real product behaves differently. Nothing was added to match a board if the backend
does not support it.

Status words: **Done** — implemented and inspected in Firefox screenshots (see `docs/UI-VERIFICATION.md`);
**Done (adapted)** — implemented with a deliberate difference listed; **N/A** — the concept does not
exist in the product and was not invented.

Evidence file names refer to the `after/` screenshot sets (Firefox, 1920 × 1080 unless stated);
`admin/`, `engineer/` and `employee/` are the personas. Numbers may shift by one or two between
runs; the `INDEX.txt` in each folder is authoritative.

| Board / screen | Route(s) · role(s) | Status | What was done · intentional differences |
| --- | --- | --- | --- |
| 01 / Sign in | `/` (signed out) · all | Done (adapted) | Split layout; refined SVG orbit with specular highlights, two rings and a dash trail that drifts slowly, pauses when the tab is hidden and stops under `prefers-reduced-motion`; matte card with glossy primary. **No SSO buttons** (Microsoft/Google/Okta are not features of this product) and no "keep me signed in" switch (sessions are server-side, fixed lifetime). |
| 02 / My Space | `/` · all | Done (adapted) | Hero with the night-sky illustration (Greg Daines, see ASSET-SOURCES) faded behind an opaque text region; search, popular chips and the person's own counters as chips in the hero; two doors (Report an issue / Request a service); **active requests first**, then "For you", then announcements. No invented request counts — every figure is the person's own data. |
| 03 / Service catalog | `/tickets/new` · all | Done | Category tiles and service cards carry glossy material tiles (one hue per service area); one marketplace grid, category tiles narrow it; approval and type on every card; **no invented fulfilment times** ("Estimated fulfilment · not configured" stays honest). |
| 04 / Request a service | `/tickets/new?service=…` (detail → `step=form` → `step=review` → `?submitted=`) · all | Done | Stepper, grouped form from the real field definitions (a VPN issue asks no hardware questions), inline validation captured (`request-form-validation`), review with the summary card, submitted state captured from a real submission on demo data. |
| 05 / Command Center | `/dashboard` · engineer, admin | Done (adapted) | Recomposed: four primary KPI cards with sparklines (Active, SLA attention, SLA compliance, CSAT), one facts strip with every secondary measure (Unassigned, Owned, In progress, MTTR, Net backlog, Inside targets, Approvals), ticket flow beside team capacity and department demand, the urgent queue full width, then attention / service areas / SLA performance, priority / work type / asset signals, live operations. Every figure keeps its denominator. Capacity bars are relative because targets are not recorded (stated on screen). |
| 06 / Service Desk | `/tickets`, `/desk`, `?…filters` · engineer, admin | Done | Pill queue tabs with counts, grouped query bar, status/priority pills, SLA emphasis, row rhythm; columns hide progressively below 1000 px and the table scrolls inside its container. |
| 07 / Work board | `/board` · engineer, admin | Done | Column headers with status accent and count, cards with priority edge, hierarchy (key, title, meta, SLA, owner). Drag, keyboard alternatives and saved views exercised by the browser suite. |
| 08 / Ticket workspace | `/tickets/:id` · engineer, admin (employees see the same route read-only) | Done | **Conversation first**: the original request opens the thread, then replies; public reply / internal note composer unmistakably separate (internal note banded and labelled); tabs Conversation · Activity · Approvals · Related. Compact details pane: SLA countdown, Properties (status/assignee/priority editable in place, "More" for category, asset, classification and dates), reviewed AI (Mock AI label), suggested knowledge, requester, followers. Pane becomes a drawer ≤ 1200 px (Escape closes). |
| 09 / My requests | `/requests`, `?tab=…`, `?sel=…` · all | Done | Split list / preview: selected request shows progress tracker, next step, updates timeline and the real "Open request" route. Full detail remains at `/requests/:id`. |
| 10 / Approvals | `/approvals`, `?tab=…` · approvers, admin | Done (adapted) | Queue beside a reviewer pane (who, what, cost when a form field records one, justification, details, note, Reject / Approve with confirmation). **No "Request changes"** — the approval model is approve or reject; a rejection requires a reason. On narrow screens the review is a dialog. |
| 11 / Knowledge home | `/knowledge`, `?q=`, `?category=` · all | Done | Category tiles first (glossy), featured "Recommended for you" card with the original laptop + shield + network illustration, most helpful and recently updated side by side; support-only / draft labels preserved for staff. |
| 12 / Knowledge article | `/knowledge/:id` · all (visibility by role) | Done | Reading measure (74ch), numbered steps rendered as counters, on-this-page navigation, related articles, helpfulness feedback in its own band. |
| 13 / Inventory | `/assets`, `?…filters` · all (scoped by role) | Done | Generic device silhouettes per type (laptop, desktop, monitor, phone, tablet, printer, network, other) drawn in SVG — **never a product render**; summary strip, filters, table. |
| 14 / Asset detail | `/assets/:id` · all (scoped) | Done | Device hero art, facts, service history, owner, lifecycle, and a warranty card with days remaining and the elapsed share (only when both dates are recorded). The fictional "Atlas 14" stays an Atlas 14. |
| 15 / People | `/people`, `/people/:id`, `?tab=requests|assets|team` · all | Done | Directory hierarchy, profile header with hue avatar (initials are the privacy-preserving default), the Assets tab carries the owner (verified by `refinement.spec.ts`). |
| 16 / Departments | `/departments`, `/departments/:id` · all (service demand for staff only) | Done | Directory and detail with manager, members, service demand (staff); no invented headcount or workload figures. |
| 17 / Service Intelligence | `/analytics`, `?days=…` · engineer, admin | Done (adapted) | Section navigation chips (Trend, Demand, SLA, Resolution, Experience, Team workload), balanced chart heights, true denominators. The page stays long by design (it is the analytical view; the Command Center is the compact one). |
| 18 / Reports library | `/reports` · engineer, admin | Done | Search, group tabs, one card per report with a **real-data preview** built from the report's own rows (sparkline of the period, met/breached bar, rating distribution, top departments/engineers) plus two summary figures. **No "Create custom report"** — there is no report builder. |
| 19 / Report workspace | `/reports/:kind?days=…` (`tickets`, `sla`, `resolution`, `csat`, `requests`, `departments`, `agents`, `assets`) · engineer, admin | Done | Each kind renders its own heading, summary, filters, rows and CSV. **An unknown kind (`/reports/demand`) is now an explicit not-found state** instead of a silent fallback to the library. The earlier "department demand / agent workload" captures were a capture-script error (wrong kind names); the real kinds are `departments` and `agents`. |
| 20 / Ask OpsPilot | `/ask`, `?q=` · all | Done (adapted) | Focused conversational workspace: starters, a session thread of question → answer with source cards, sticky composer, Mock AI label and usage. **No stored chat history** (the backend keeps none, the page says so) and **no ticket questions** (knowledge-only scope). |
| 21 / Notifications | `/notifications` · all | Done | Day-grouped inbox with a selected-message pane (kind, full text, ticket, Open / Mark as read), tabs, and the real preference switches. |
| 22 / Account & security | `/account` · all | Done (adapted) | Profile card, **App preferences with the real theme control** and a link to notification settings, two-factor, bounded password form (≤ 440 px), sessions, data export. Density and language switches do not exist in the product and were not added. |
| 23 / Command search | Ctrl K · all | Done | Grouped results (pages, actions, tickets, people, knowledge, assets, departments, services), selected row, keyboard operation, Escape/outside dismissal; verified by `workspace.spec.ts`. |
| 24 / Resolve ticket | `/tickets/:id` → Resolve · engineer, admin | Done (adapted) | Dialog with context and summary validation (≥ 10 characters). **No resolution category or "notify requester" switch** — the product records no resolution codes and always notifies the requester with the summary. |
| 25 / Admin overview | `/admin` · admin | Done | Fact cards (accounts, departments, catalog, service levels, sessions, locked), grouped configuration areas with tiles, and a **recent audit activity** panel fed by the real audit log. |
| 26 / Accounts & access | `/admin/users` · admin | Done | Table with role/access/MFA/last sign-in and Manage menu; **account creation in its own drawer** with designed inline validation (nothing is posted until it passes — pinned by `refinement.spec.ts`). |
| 27 / Roles & permissions | `/admin/roles` · admin | Done | Role cards and a scannable capability matrix (centred yes/no, zebra rows). Read-only: roles are fixed and enforced by the API. |
| 28 / Service levels | `/admin/sla` · admin | Done (adapted) | Policy list beside an **edit pane for the selected priority** (response and resolution targets in minutes with human-readable hints, "applies to new tickets" note). **Service hours are 24/7 only** — the business-hours option in the board does not exist and is not offered. |
| 29 / Catalog admin | `/admin/catalog` · admin | Done | Item table with Preview / Edit and a bounded editor column with grouped fieldsets (approval, form fields). |
| 30 / Templates & workflow | `/admin/templates`, `/admin/workflow` · admin | Done (adapted) | Template table and editor; workflow page adds a **read-only lifecycle visualisation** (Open → In progress → Waiting → Resolved → Closed with the SLA clock state) above the transition table and priority matrix. Transitions are not editable in this release and are marked so. |
| 31 / Announcements | `/admin/announcements` · admin | Done | List · editor · **live preview** that reads the form state (title, message, audience, pinned, expiry) exactly as My Space will show it. |
| 32 / Audit & platform | `/admin/audit`, `/admin/outbox`, `/admin/ai`, `/admin/security`, `/admin/data` · admin | Done (adapted) | Audit log with search, action groups, CSV and an **event inspector** for the selected row (timestamp, actor, action, resource, visibility, recorded detail). The log stores no before/after snapshots beyond the detail text, so none are fabricated. Outbox, AI & retrieval, Security and Data & retention remain separate, complete pages. |
| Empty / no-results states | Service Desk, Knowledge, Assets, Reports, inbox, approvals · all | Done | Same `EmptyState` component; captured for desk and knowledge (`state-desk-no-results`, `state-knowledge-no-results`). |
| Forbidden / not found | `/admin`, `/analytics`, `/reports` for employees; `/knowledge/new` for non-admins; unknown routes; unknown report kinds | Done | One `StatePage` shape (mark, code, title, explanation, way out). `/knowledge/new` for an engineer is a designed 403 ("Only administrators write knowledge articles"), not a generic load error and not an article lookup. |
| Loading | every data view | Done | Layout-shaped skeletons; the Command Center skeleton mirrors the new composition. |
| Disabled / long text | buttons, AI limits, long titles | Done | Disabled primaries lose sheen and lift; long titles wrap (`overflow-wrap: anywhere`) in headers, previews and inspectors. |
| Light theme | all routes · `data-theme="light"` | Done | Same shapes on a bright field; axe 0 violations on 29 pages; sets in `after-light/`. |
| Phone (390) / tablet (1024) / laptop (1440) | all routes | Done | No page-wide horizontal overflow at 360/390/1024/1366/1440/1920 (tables scroll in their own containers); details pane and navigation become drawers; sets in `after-390/`, `after-1024/`, `after-1440/`. |
| Reduced motion | all routes · `prefers-reduced-motion: reduce` | Done | Orbit animation `none`, control and dialog durations collapse to 0.01 ms, hover lift removed; measured in `evidence/motion/motion-reduced.txt`. |

## Evidence problems from the audit, resolved

| Finding | Root cause | Resolution |
| --- | --- | --- |
| `report-department-demand` / `report-agent-workload` showed the library | Capture script used `/reports/demand` and `/reports/workload`; the kinds are `departments` and `agents`. | Script fixed; every kind is captured with its unique heading asserted. Product improvement: unknown kinds now render a not-found state instead of the library. Test: `refinement.spec.ts`. |
| `request-detail` for admin/engineer showed the catalog | The script clicked the first link in the page ("Request something"). | Script selects only `a[href*="#/requests/"]`; when the persona has no request it writes an explicit `N/A` line instead of a wrong picture (admin and engineer have raised nothing in the seed). |
| `person-assets` showed the whole inventory | The script matched the sidebar "Assets" link, not the profile tab. | Script clicks the tab inside `main`; captured URL carries `?tab=assets`. Test: `refinement.spec.ts`. |
| engineer `/knowledge/new` showed a load error | The page rendered a generic `ErrorState` ("Something did not load") for a permission case. | Designed 403 state; "New article" affordance was already hidden for non-admins. Test: `refinement.spec.ts`. |
| Account menu open over other pages | Real defect: the menu closed only on outside click; Escape and navigation were ignored. A second cause was found while fixing: React re-renders the route in a microtask between the app's `hashchange` handler and the menu's, so a listener re-registered on every render was removed mid-dispatch. | `useDismiss` (outside click, Escape, navigation) with a stable listener, applied to the account menu, create menu, bell and every `Menu`. Reproduced in the "before" Firefox run (`-- DEFECT` lines in `before/*/INDEX.txt`) and pinned by `refinement.spec.ts`. |
| "Create user dialog" was an inline form with a native bubble | Naming error plus an undesigned validation state. | Creation moved to a drawer with designed inline validation; captures are named `admin-add-account-drawer` and `admin-add-account-validation`. |
